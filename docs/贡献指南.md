# 贡献指南

感谢你参与 API Monitor。当前项目使用 React + Kumo 前端和 Go + SQLite 后端，贡献时请优先遵守现有模块边界与 Kumo-only UI 规则。

## 环境要求

- **前端**: Node.js 20 LTS 或更高版本，npm 9 或更高版本
- **后端**: Go 1.23 或更高版本
- **Agent**: Rust 1.75 或更高版本（仅在维护 `agent-rust/` 时需要）
- **数据库**: SQLite（Go 后端内置支持）

## 本地开发

```bash
git clone https://github.com/iwvw/api-monitor.git
cd api-monitor

# 前端开发
npm install
npm run dev          # 启动 Vite 开发服务器 (http://localhost:5173)

# 后端开发
cd backend-go
go build -o api-monitor.exe ./cmd/api-monitor
./api-monitor.exe    # 启动 Go 后端 (http://localhost:3000)
```

生产构建：

```bash
# 前端构建
npm run build

# 后端构建
cd backend-go
go build -o api-monitor ./cmd/api-monitor
```

## 常用命令

**前端:**
```bash
npm run lint
npm run lint:fix
npm run build
npm run test
npm run format:check
```

**后端:**
```bash
cd backend-go
go test ./...                    # 运行测试
go build ./cmd/api-monitor       # 构建
go run ./cmd/api-monitor         # 直接运行
```

前端样式或交互改动至少运行 `npm run lint` 与 `npm run build`。涉及路由、弹窗、表格、图表、导航、移动端布局时，还应做浏览器验证。

## 代码规范

**前端:**
- 前端基础 UI 必须优先使用 `@cloudflare/kumo`。
- 不新增自绘 Button、Input、Select、Tabs、Table、Dialog、Toast、Checkbox、Switch、Sidebar、Loader 等 UI 组件。
- 不硬编码主题色，使用 `bg-kumo-*`、`text-kumo-*`、`border-kumo-*`、`ring-kumo-*` 等 token。
- 按钮默认使用 `size="sm"`；与 Input、Select、Tabs 同排时保持高度一致。
- 删除确认优先迁移到 Kumo `DeleteResource`。
- 表格内容默认不换行，数据密集表格优先支持 `Table.ResizeHandle`。
- 图表使用 Kumo Chart 系列，颜色使用 `ChartPalette`，加载期使用 `loading` 骨架。

**后端:**
- 遵循 Go 标准项目布局
- 使用标准库优先，第三方依赖需评审
- 所有 API 端点需要单元测试
- 数据库操作使用事务保证一致性
- 日志使用结构化格式

详细 UI 约束见 [KUMO_MIGRATION_RULES.md](./KUMO_MIGRATION_RULES.md)。

## 项目结构

```text
api-monitor/
├── backend-go/            # Go 后端服务
│   ├── cmd/api-monitor/   # 主程序入口
│   └── internal/          # 内部包（路由、服务、数据库等）
├── agent-rust/            # Rust Agent 客户端
│   └── src/               # Agent 源码
├── src/
│   ├── js/                # React 前端
│   │   ├── components/    # 壳层与少量业务辅助组件
│   │   ├── pages/         # 主页面
│   │   ├── modules/       # 前端运行时 helper
│   │   └── store.js       # Zustand 全局状态
│   └── css/app.css        # Tailwind/Kumo 样式入口
├── docs/                  # 项目文档
├── data/                  # 数据目录（运行时生成）
└── dist/                  # 前端构建产物
```

## 提交规范

使用 Conventional Commits：

```text
feat(server): add host metric endpoint
fix(ui): align compact toolbar controls
docs(kumo): update component registry notes
```

常用类型：

- `feat`：新功能。
- `fix`：修复问题。
- `docs`：文档更新。
- `refactor`：重构。
- `perf`：性能优化。
- `test`：测试。
- `chore`：工具、依赖或构建变更。

## PR 检查清单

# 新模块接入指南

最后更新：2026-06-07

本指南用于新增或大改业务模块。当前项目默认使用 React + Kumo 前端和 Express + SQLite 后端，不再新增旧 Vue 模板。

## 1. 明确模块 ID

模块 ID 应短小、稳定，并与路由和设置保持一致，例如：

- `openai`
- `gemini-cli`
- `server`
- `cloudflare`
- `notification`

后端模块目录建议使用 `modules/<feature>-api/`，例如 `modules/example-api/`。

## 2. 后端模块

推荐结构：

```text
modules/example-api/
├── router.js
├── storage.js
├── schema.sql
└── README.md
```

要求：

- `router.js` 导出 Express router。
- `schema.sql` 必须幂等，使用 `CREATE TABLE IF NOT EXISTS`。
- 表名带模块前缀，避免与其他模块冲突。
- storage 层集中处理数据库读写，不在 router 中散落 SQL。
- 输入必须校验，敏感写接口要考虑鉴权和 2FA。
- 模块内部不要直接依赖其他模块表的外键。

## 3. 路由注册

大多数 `modules/*-api/router.js` 会由 `src/routes/index.js` 挂载。特殊路由、公开 API、代理路径或认证豁免必须在 `src/routes/index.js` 中显式登记。

新增外部可调用 API 时，确认：

- 是否需要 `requireAuth`。
- 是否需要限流。
- 是否需要 public base URL。
- 是否需要写入调用日志。
- 是否暴露在 `/v1` 或 OpenAI-compatible 接口中。

## 4. 前端页面

新增页面：

```text
src/js/pages/ExamplePage.jsx
```

然后更新：

1. `src/js/store.js` 的 `MODULE_CONFIG`。
2. `src/js/store.js` 的 `MODULE_GROUPS`。
3. `src/js/components/MainLayout.jsx` 的 import。
4. `MainLayout` 中的 icon 映射。
5. `renderActivePage()` 的 switch case。

模块 path 默认是 `/<moduleId>`。如果需要特殊 path，更新 `MainLayout` 中的 path 映射逻辑。

## 5. 设置同步

用户设置会管理模块显隐和顺序。新增模块后确认：

- `DEFAULT_MODULE_ORDER` 包含该模块。
- `DEFAULT_MODULE_VISIBILITY` 自动包含该模块。
- 后端 `src/services/userSettings.js` 不会过滤掉该模块。
- 设置页能显示、排序、保存并恢复该模块。

## 6. 前端 UI 约束

- 使用 Kumo 组件，不新增通用 UI 封装。
- 按钮默认 `size="sm"`。
- 与 Input/Select 同排时保持相同尺寸。
- 表格使用 Kumo `Table`，数据密集时支持列宽拖动。
- 图表使用 Kumo `TimeseriesChart` / `Meter`，颜色使用 `ChartPalette`。
- 删除确认使用 Kumo `DeleteResource`。
- 复制命令、URL、token 使用 `ClipboardText`。
- 使用 Kumo token，不硬编码主题色。

## 7. 空态、加载和错误

每个页面至少处理：

- 首次加载。
- 空数据。
- API 失败。
- 保存中或删除中。
- 窄屏布局。
- 暗色主题。

加载占位使用 Kumo `SkeletonLine` 或 Kumo Chart 的 `loading` 状态。不要用本地自绘 loader。

## 8. 验收

至少运行：

```bash
npm run lint
npm run build
```

新增页面还要做浏览器 smoke：

- 直接访问路由不白屏。
- 侧栏高亮正确。
- 空数据可读。
- 主要弹窗可打开关闭。
- 控制台无 React runtime error。
- 窄屏下内容不重叠。

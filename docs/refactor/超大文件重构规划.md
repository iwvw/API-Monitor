# 超大文件重构规划

> 本文件是 `refactor/large-files` 分支重构的唯一执行依据。所有子代理必须严格照本文件执行，不得自行发挥。
> 生成依据：对全部 66 个 >1000 行业务文件的结构侦察（前端 24 + 后端 42）。
> 上游提示词：`docs/refactor/超大文件重构提示词.md`。

---

## 0. 总原则

1. **机械拆分**：只做文件级搬移 + import/export 调整，不改任何逻辑、签名、字符串、路由、SQL、schema。
2. **同包拆文件**：后端严格限制在同 package 内拆文件，**绝不新建子包**（避免 import 环与 `*Service` 接收者问题）。
3. **Service 结构体不拆**：所有 `*Service` 字段保持原样，方法按功能簇搬到新文件。
4. **类型定义归位**：被多文件引用的 type/const/SQL 字符串留在 `service.go` 或集中到 `types.go`，不散落。
5. **ServeHTTP / 路由分发不动**：保持在 `service.go`，路由清单零漂移。
6. **命名契约**：后端 `<domain>_<sub>.go` / `service.go` / `schema.go` / `types.go` / `helpers.go`；前端 `constants.js` / `utils.js` / `useXxx.js` / `XxxPanel.jsx`。
7. **每批独立验证**：`go build ./...` + `go vet ./...` + `go test ./...`；前端 `npm run lint` + `npm test`。每批后跑快照比对。

## 1. 执行批次总表

批次按「风险从低到高、依赖从叶子到根」排序。同一批次内文件之间无交叉，可并行。

| 批次 | 域 | 文件 | 并行度 | 特殊约束 |
|---|---|---|---|---|
| **B1** | 后端叶子 | subscription(uri_parse/mihomo_validate), uptime(probe/jsonpath/helpers), cloudflare(helpers/transport), notification(helpers) | 4 并行 | 纯 leaf，零风险 |
| **B2** | 后端 schema | subscription, uptime, cloudflare, notification, m365, serveragent 的 schema 拆分 | 6 并行 | 只移 SQL/迁移，不动执行顺序 |
| **B3** | 后端模块 CRUD | cloudflare(accounts/templates/zones_dns/analytics/workers/pages/r2/tunnels), notification(handlers/store/history/config), m365(accounts/graph/users/licenses/groups/invites/registrations/credentials/helpers/public_pages 系) | 3-4 并行 | 同包，类型留 service.go |
| **B4** | 后端 openai | relay(loop/chat/responses/errors/models), service(types/lifecycle/schema/serve/routing_cache/background/upload), endpoints(crud/verify/models/subscription/sync), proxypool(client/state/select/latency/keys/response/debug) | 4 并行 | openai 包内自洽 |
| **B5** | 后端 adminai | engine(run/events/llm/catalog/tools/results/session/settings) | 1-2 并行 | 事件总线跨文件，需成组 |
| **B6** | 后端 uptime 运行态 | uptime(scheduler/check/incident/maintenance/statuspage/metrics/ssl/monitor/portability/config_normalize) | 1 串行 | 共享 s.mu/checkLocks/timers，必须成组迁移 |
| **B7** | 后端 subscription 主体 | subscription(service/plan/nodes/node_import/profile/upstream/render/mihomo_render/public_serve/ledger/store_loaders/templates_crud/admin) | 1 串行 | subscriptionExecutor 接口需同文件 |
| **B8** | 后端 serveragent | service(service_events/schema/status_pages/credentials_snippets/monitor/accounts/account_response/metrics_util/cached_info), server_ops(sftp/docker_routes/agent_tasks/json_helpers), managed_forwards(deploy/reconcile/health), managed_proxy_nodes(identity/apply) | 1 串行 | **单所有者文件**，必须独占；先提取闭包 |
| **B9** | 前端叶子 + 目录迁移 | 各页面的 constants/utils 搬迁 + 模块目录建立与 `components/<module>/` 迁入（方案 A） | 6-8 并行 | 只搬纯常量/纯函数 + 移动文件 |
| **B10** | 前端面板 | 各页面的子组件/面板/弹窗拆分 | 4-6 并行 | 每文件独立 |
| **B11** | 前端 hooks | 各页面的状态簇抽 hook | 2-3 并行 | 风险最高，最后做 |
| **B12** | 前端 super | ServerPage 专项（112 个 useState） | 1 串行 | 单所有者；先搬前 2465 行纯部分 |

**执行顺序**：B1 → B2 → B3 → B4 → B5 → B6 → B7 → B8 →（前端）B9 → B10 → B11 → B12。

**并行上限**：同一时刻 ≤4 个子代理（避免写冲突）；单所有者文件相关批次（B8、B12）强制独占。

## 3. 前端逐文件拆分映射

前端 24 个文件统一遵循 CONTEXT.md 的拆分顺序：**常量/纯函数 → hooks → dialogs → tables/panels → 容器**。

### 3.1 前端统一命名契约

| 内容 | 目标文件 | 规则 |
|---|---|---|
| 纯常量、配置映射、枚举 | `constants.js` | 无 import 运行时模块 |
| 纯函数（格式化/计算/无副作用） | `utils.js` | 不得 import 组件 |
| 自定义 Hook | `useXxx.js` | 封装一个独立状态域 |
| 子组件/弹窗/面板/表格 | `XxxPanel.jsx` / `XxxDialog.jsx` / `XxxTable.jsx` | 一个可独立命名的 UI 单元一个文件 |
| 页面容器 | `XxxPage.jsx` | 只留编排 |

### 3.2 目标目录结构（方案 A：模块私有文件全部收拢到 `pages/<module>/`）

**核心规则**：
1. 每个模块在 `src/js/pages/<module>/` 下拥有一个目录，存放该模块的容器 + 私有 constants/utils/hooks/panels/dialogs。
2. 模块私有的现有 `components/<module>/` 文件**迁入**对应 `pages/<module>/`。
3. `components/` 只保留**真正跨模块共享**的内容与已有独立模块：
   - `components/ui/`（通用 UI 原语，全站引用）
   - `components/public/`（被 6 个公开页共享，保持不动）
   - `components/editor/`（文档编辑器模块，已是独立模块）
   - `components/drawio/`（drawio 模块）
   - `components/forward/`（转发中心模块）

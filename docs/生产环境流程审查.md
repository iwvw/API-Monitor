# 生产环境流程审查

更新时间：2026-06-16

## 已确认问题

### 1. Docker healthcheck 路径错误

- 现象：Dockerfile 之前检测 `/api/health`。
- 实际：Go 后端健康检查是 `/health`。
- 影响：容器会被错误判定 unhealthy。
- 处理：已修正为 `/health`。

### 2. Agent 一键安装脚本下载路径不一致

- 现象：Linux/Windows 安装脚本之前访问 `/downloads/...`。
- 实际：生产镜像静态目录是 `/agent/...`。
- 影响：一键安装在生产镜像中下载失败。
- 处理：已修正为 `/agent/agent-linux-{amd64|arm64}` 和 `/agent/agent-windows-amd64.exe`。

### 3. Dockerfile 依赖“可选预编译二进制”

- 现象：构建阶段假定本地一定存在 Agent 二进制。
- 影响：本地构建、首次 CI 构建容易失败。
- 处理：已改成复制整个 `agent-rust/` 目录，再按需现场编译 Linux Agent。

### 4. 前端测试在迁移期无测试文件时会失败

- 现象：`npm run test` 在没有 `test/**/*.test.js` 时退出码 1。
- 影响：CI PR / push 会失败。
- 处理：已改为 `vitest run --passWithNoTests`，避免迁移收口期误伤流程。

### 5. ESLint 被设为容错

- 现象：CI 里 `npm run lint` 之前允许失败。
- 影响：前端质量门禁失效。
- 处理：已恢复为硬门禁。

### 6. Release 过早发布

- 现象：Release 在资产未完成前就可能变为正式发布。
- 影响：失败时留下不完整发布记录。
- 处理：已改为先 draft，全部构建/上传完成后再 publish。

### 7. Docker Compose 暴露默认密钥

- 现象：`docker-compose.yml` 之前写死 `ADMIN_PASSWORD` 和 `JWT_SECRET`。
- 影响：示例配置容易被直接用于公网生产，造成默认密码或固定会话密钥风险。
- 处理：已改成必须通过宿主机环境变量注入；未设置时 compose 启动会失败。

## 仍需关注

- 生产环境仍建议把 `ADMIN_PASSWORD` 和 `JWT_SECRET` 接入密钥管理或部署平台 secret，而不是写入仓库或 compose 文件。
- `.github/workflows/*` 里还存在若干 `continue-on-error: true`，其中部分是可接受的容错（如 Codecov、Docker Hub 登录），但安全扫描和发布链路应继续收紧。
- 生产镜像的 Agent 分发路径和前端下载链接要保持长期一致，后续新增平台时必须同步更新安装脚本、Dockerfile、Release 文案和前端下载按钮。
- 目前 Vitest 测试目录处于迁移期，后续应恢复至少一组核心前端测试，不能长期依赖 `--passWithNoTests`。

## 建议的生产发布门禁

1. `npm run lint`
2. `npm run build`
3. `npm run test`
4. `cd backend-go && go test ./...`
5. `cd agent-rust && cargo check`
6. 构建 Docker 镜像并验证 `HEALTHCHECK`
7. 发布 Release 前先保持 draft
8. 发布后再打最终正式状态

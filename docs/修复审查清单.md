## 二、高危 13 项（逐项修复路径）

### 1. Agent 安装脚本公网口泄露凭证（manifest.go / routes.go）
- 问题：`/api/server/agent/install/linux/{id}` 注册为 AuthPublic 且无 key 校验，直接返回含 AGENT_KEY 的脚本
- 修复：删除该路由（manifest 与 handler 分支），仅保留 `{id}/{key}` 变体；路由清单确认无 key 变体消失
- 测试：`serveragent/service_test.go` TestAgentQuickInstallCreatesHostFromName 增断言（无 key→404 且不泄露）

### 2. socket.io 匿名伪造心跳/状态（engineio.go / service.go）
- 问题：CONNECT 无条件 Authenticated=true；未认证会话可直接发 agent:state 采信 payload server_id 改主机状态
- 修复：CONNECT 不再置认证位；事件门禁——除 authenticate/agent:connect 外的事件必须已认证且 ServerID 非空，否则丢弃并记日志
- 测试：TestAnonymousSessionCannotForgeAgentState（伪造三事件不落库）+ TestAuthenticatedSessionStateUpdatesHost（正例）

### 3. OpenAI 网关 /uploads 路径穿越（openai/service.go）
- 问题：`HasPrefix("/uploads/")` + filepath.Join(DataDir,...) 可穿越读取任意文件；与回环免密钥叠加放大（回环放行属设计意图，未改）
- 修复：新增 `safeUploadPathJoin`（Clean 后必须落在 DataDir/uploads/ 内）+ `inlineLocalUploadImage` 统一入口
- 测试：TestSafeUploadPathJoin（13 例穿越/编码/边角）+ TestInlineLocalUploadImageRejectsTraversal；**首版包含性校验过宽（可逃到 DataDir 根）被测试抓出后收紧**

### 4. 通知模板渲染死循环（notification/service.go）
- 问题：缺失 key 时 replacement 重建为相同文本，for{} 无出口，冻结监控检查链
- 修复：游标式单遍扫描（缺失占位符原样保留且不再回扫），终止性由结构保证 + 迭代上限兜底
- 测试：TestRenderTemplateTerminatesOnMissingKeys（含 500 占位符压力例）

### 5. uptime 并发 check 重复 incident（uptime/service.go）
- 问题：定时器链/checkNow/startMonitor 可并行跑同一 monitor 的 check，processState 非原子读改写 → 重复 incident + 可用率永久偏低
- 修复：`lockMonitor` per-monitor 互斥，`s.check` 入口统一串行化
- 测试：TestConcurrentChecksDoNotDuplicateIncidents（4 goroutine 并发 → 断言仅 1 条 incident）

### 6. AI 自批审批 + 审批决议丢失（server/ai_caller.go / adminai）
- 问题：ai_caller 直调 serveGoRoute 绕过会话鉴权，只拦 /api/ai/；approval channel 注册在 INSERT/emit 之后，窗口内决议静默丢失
- 修复：黑名单加 `/api/admin-ai/`；channel 注册提前到 INSERT 前；resolve 的 RowsAffected=0 → 409"已过期或已处理"
- 测试：TestAIMCPCannotSelfApproveAdminRoutes；TestResolveApprovalTwiceDenied 断言更新为 409

### 7. M365 公开注册契约断裂（m365/service.go）
- 问题：前端不发 password，后端硬性要求且不生成；响应无 initialPassword 但前端渲染
- 修复：password 为空时自动生成（12 位混合字符）并随响应返回 initialPassword 一次
- 测试：既有的 TestInviteRegistrationLifecycle **此前一直红**，修复后转绿（契约断裂的直接证据）

### 8. SSE 60s WriteTimeout 静默死亡（新增 internal/sseutil）
- 问题：全局 WriteTimeout 60s 是绝对截止，github/publicPage/analytics/streamTask/handleCronTaskRun 五个流未续期
- 修复：`sseutil.RenewWriteDeadline`（每写前续期 10min，ErrNotSupported 宽容）接入全部五个流
- 测试：sseutil_test.go

### 9. 数据库导入热替换损坏（database/connpool.go / settings/service.go）
- 问题：替换活跃库文件不处理连接池，POSIX 写旧 inode / Windows 替换失败
- 修复：`ResetPool`（替换前后各失效一次连接池，新连接读新文件）+ 与 VACUUM 互斥检测（vacuumRunning）
- 已知局限：进程常驻句柄仍指向旧文件，导入成功后需重启后端（注释与文档已说明）
- 测试：TestResetPoolInvalidatesAndRebuilds

### 10. 前端流式打字机卡首块（MessageList.jsx / modules/typewriter.js）
- 问题：textRef 只在整体替换分支推进，delta 追加时停在首 chunk
- 修复：`typewriterFrame` 纯函数区分 reset/extend，增量追加继续揭示
- 测试：typewriter.test.js（4 例）

### 11. toast 被当函数调用（ServerPage.jsx）
- 问题：9 处 `toast({...})`（比报告多 1 处），toast.js 导出对象 → TypeError
- 修复：全部改 `toast.show({...})`；全仓 grep 确认零残留
- 测试：eslint

### 12. metrics hub 阻塞式广播（metrics_hub.go）
- 问题：同步无 deadline 遍历写所有订阅者，慢客户端卡死 agent 处理链
- 修复：每次写前 SetWriteDeadline(3s)，超时踢出
- 测试：TestMetricsHubBroadcastRemovesDeadClient

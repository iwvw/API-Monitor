# 待办任务闭环流程

最后更新：2026-09-03

本文档记录待办任务（GitHub Issues，标签 `backlog`/`in-progress`/`done`）从查看进度到关闭完成的标准操作流程。规则层约定见 `CONTEXT.md` 的「Multi-Window Agent Collaboration · Task Tracking」一节；本文只写具体怎么操作。

## 1. 查看待办进度

列出所有未关闭 issue，按标签区分 backlog / in-progress：

```bash
gh issue list --state open --limit 50
```

查看单个 issue 详情（body / labels / comments）：

```bash
gh issue view <编号> --json title,state,labels,body,comments
```

issue body 是指针式的（指向 `docs/多Agent协作登记.md`），真实细节在仓库文件里，不要只读 issue 本体。要看某个任务是否真的落地，用 git log 对照：

```bash
git log dev --oneline --grep="关键词1\|关键词2"
```

## 2. 判断任务是否完成

完成判据 = 对应功能的 commit 已进 `dev` 且验证命令通过，不是看 issue 标签。

- `git log --grep` 能命中该任务相关 commit，说明代码已落地。
- 用 `git log origin/dev..dev --oneline` 看哪些是本地领先、未推送的提交。
- 每个 commit 的验证命令写在 commit message 里，逐条跑 `go test ./internal/<模块>/`、`go vet`、`go build ./...`、`npm run lint`、`npm run governance:check` 等确认。

一个已知坑：代码已合并但 issue 忘记打 `done`/关闭，会造成"in-progress 但其实已完成"的假象。遇到这类 issue，直接走第 3 步闭环，不要继续等。

## 3. 关闭已完成 issue（标准三步）

先加 `done` 标签，再移除 `in-progress`，最后关闭并附完成说明。`gh issue close` 没有 `--label` 参数，标签必须用 `gh issue edit` 单独管理：

```powershell
# 1) 加 done 标签
gh issue edit <编号> --add-label done

# 2) 移除 in-progress（只留 done）
gh issue edit <编号> --remove-label in-progress

# 3) 关闭，comment 里写清实现要点 + 验证命令
gh issue close <编号> -r completed -c "实现要点与涉及 commit；验证：go test ./internal/<模块>/、go vet、go build ./...、npm run governance:check"
```

批量处理多个 issue 时用 PowerShell 循环：

```powershell
foreach ($n in 19,20,21,22,23) { gh issue edit $n --add-label done }
```

注意 PowerShell 的 `foreach ($n in ...) { ... }` 语法，不要用 bash 的 `for n in ...; do`，本机 shell 是 pwsh。

## 4. 常见坑速查

| 现象 | 原因 | 处理 |
|---|---|---|
| `unknown flag: --label` | `gh issue close` 没有 `--label` 参数 | 用 `gh issue edit --add-label` / `--remove-label` |
| 关闭后还挂着 `in-progress` | 只加了 `done` 没删旧的 | `gh issue edit <编号> --remove-label in-progress` |
| `for n in ...; do` 报 ParserError | 本机是 PowerShell | 改用 `foreach ($n in ...) { ... }` |
| issue 还在 open 但代码已合并 | 忘记闭环 | 按第 3 步直接关闭，附验证命令 |
| backlog 长期不动的任务 | 排队中的 backlog，未开始 | 不要关闭，保持 `backlog` 即可 |

# 安全加固与扫描计划

## 环境边界

- 开发环境使用 `APP_ENV=development`，允许本地 HTTP 和本地 Shell 任务，前端通过 Vite 同源代理访问 Go 服务。
- 生产环境使用 `APP_ENV=production`，应在 HTTPS 反向代理后运行。会话 Cookie 默认 `Secure`，本地 Shell 任务默认关闭。
- 生产环境只有显式配置在 `TRUSTED_PROXY_CIDRS` 中的代理才会影响客户端 IP 和登录限流。
- 跨域访问必须配置 `CORS_ALLOWED_ORIGINS`，同源部署保持为空。

## 已完成的高优先级修复

- 管理员密码不再写入 `localStorage`，登录响应不再返回会话 ID。
- 会话 Cookie 在生产环境启用 `Secure`、`HttpOnly`、`SameSite=Lax`。
- 浏览器插件改用 `akp_` 开头的独立只读 API Key，仅能读取 `GET /api/totp/accounts`，可监控、过期、轮换或撤销。
- 插件推荐使用 `pair_` 一次性高熵配对码，10 分钟内仅可兑换一次；TOTP 原始密钥不会下发到浏览器。
- 插件 API Key 与主程序会话状态联动：至少存在一个有效主程序登录会话时才允许取码，全部会话下线后立即停止。
- “系统设置 → 安全”展示有效登录设备的 IP、浏览器、最后活动与到期时间，并支持单台或全部强制下线。
- 插件令牌保存在 `chrome.storage.local`，不再进入浏览器同步存储；跨页面 `postMessage` 自动同步已移除。
- 插件展示的账号、发行方、验证码和错误信息经过 HTML 转义，插件不再接受任意网页注入配置。
- 生产环境本地 Shell 调度任务默认拒绝，必须显式设置 `ALLOW_LOCAL_SHELL_TASKS=true`。
- 去除通配符 CORS、收紧会话跨来源请求，并限制 SSH/Engine.IO WebSocket 来源。
- Go HTTP 服务增加请求头、读写和空闲连接超时。

## CI 扫描门禁

`security.yml` 已在 PR / push / 定时三种模式下落地以下硬门禁（任一失败即阻止合并）：

```text
npm audit --audit-level=high
govulncheck ./...
cargo audit
gitleaks detect --redact
```

以下两项仍在计划中，尚未接入 CI：

```text
semgrep scan --config auto
trivy fs --scanners vuln,secret,misconfig .
```

发布镜像前额外运行 Trivy 镜像扫描（`release.yml` 的 security-scan job，`continue-on-error`）、Syft SBOM 生成、镜像签名和来源证明。

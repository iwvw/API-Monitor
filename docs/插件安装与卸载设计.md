# 插件安装与卸载设计

最后更新：2026-08-29

本文定义模型网关插件（如「代理池」这类挂进 `OpenAIPluginsPanel` 的模块）的**安装登记**与**快速卸载**规范，目标是让 AI 或维护者能在不破坏主程序的前提下，用最少步骤完整删除一个插件（代码 + 路由 + 表 + 前端 + 依赖）。

## 核心原则

1. **插件必须自包含**：后端代码放独立目录（如 `backend-go/internal/proxypool/`），前端组件放 `src/js/pages/openai/plugins/<PluginID>.jsx`。禁止把插件逻辑散落在主模块文件里。
2. **每装必登记**：安装/开发插件时，在 `docs/plugins/registry.json` 追加一条，如实记录所有改动点。这是卸载的唯一依据。
3. **卸载 = 登记清单逐项回滚**：按 `registry.json` 的 `uninstallSteps` 删除即可，不需要靠记忆或全文搜索。
4. **接线点集中**：后端只允许动 3 个文件——`manifest.go`（前缀）、`server.go`（字段 + New + 注入 + case）、`go.mod`（依赖）。前端只允许动 2 个——`OpenAIPluginsPanel.jsx`（注册表）、插件自身文件。

## 登记清单格式

见 `docs/plugins/registry.json`。每个插件记录：

| 字段 | 内容 |
|---|---|
| `backendDirs` | 后端包目录（整个目录可删） |
| `manifest.lines` | manifest.go 中该插件的路由前缀行（逐字匹配删除） |
| `serverWiring` | server.go 的 import / struct 字段 / 构造 / 注入 / ServeHTTP case |
| `dbTables` | 插件建的 SQLite 表（DROP 即可） |
| `dbColumnAdds` | 插件在既有表上新增的列（需注意其它模块可能引用，卸载时先清数据） |
| `frontend.files` | 前端组件文件 |
| `frontend.registrations` | 注册表条目（文件 + 插件 id） |
| `goDeps` | 插件引入的 Go 依赖（`go mod tidy` 会自动移除） |
| `systemContracts` | system 目录（route_contracts.go 等）里登记的契约行 |
| `docs` | 插件配套文档 |
| `uninstallSteps` | 逐条卸载命令（AI 直接执行） |

## 卸载流程（AI 执行）

以删除插件 `<id>` 为例：

```bash
# 1. 读登记清单，确认 <id> 的所有改动点
node -e "const r=require('./docs/plugins/registry.json'); console.log(JSON.stringify(r.plugins['<id>'],null,2))"

# 2. 删后端目录
rm -r backend-go/internal/<id>

# 3. 从 manifest.go 删前缀行（逐字匹配 registry.lines）
# 4. 从 server.go 删 import / 字段 / New / 注入 / case
# 5. 删前端组件文件 + 注册表条目
# 6. 删 DB 表（PASSIVE 维护，见下）
# 7. go mod tidy && go build ./... && go test ./internal/manifest/ ./internal/server/
# 8. npm run lint && npm run build && npm run governance:check && npm run ui:governance
# 9. 更新 registry.json 移除该条目
```

## 数据库卸载

- 插件自建表直接 `DROP TABLE`。
- 插件在既有表加的列（如 openai_endpoints.proxy_pool_id）：**不能直接 DROP COLUMN**——先确认无其它模块引用，若有先清空引用数据，必要时保留列但不再使用。
- 周期 WAL 维护只做 PASSIVE（见 CONTEXT.md 红线），卸载建表/删表都走正常连接，不触发 checkpoint。
- 卸载表时后端进程可能持有连接，用 `busy_timeout` 短事务执行即可。

## 新增插件时的登记流程

1. 起独立包目录 + 独立前端文件，风格参照 `docs/模型网关插件开发指南.md`。
2. 后端接线只动 manifest.go / server.go；如引入新依赖记录 `goDeps`。
3. 全部改动完成后，在 `docs/plugins/registry.json` 追加条目（含 `uninstallSteps`）。
4. 在 `docs/多Agent协作登记.md` 登记任务，避免与其它窗口冲突。

## 引擎类插件目录约定

- 后端包根目录放插件 Service/handlers（设置、路由、授权、转发）。
- 引擎源码整体放 `<插件>/engine/` 下，import 前缀统一改为 `github.com/iwvw/api-monitor/backend-go/internal/<插件>/engine/...`。
- 引擎内 `internal/` 目录会触发 Go internal 访问限制（外层 Service 无法导入），一律重命名为 `core/`。
- 引擎依赖记录进 `goDeps`，卸载时 `go mod tidy` 自动清理。
- 引擎配置优先落盘到 `data/<插件>/`（如 `data/ds2api/config.json`），由 Service 在启停时读写。

# 模型网关插件中心开发指南

最后更新：2026-08-29

本文档沉淀「模型网关 → 插件中心」的插件结构、样式约定与接入方式，供后续新增插件直接复用。

## 插件中心机制

插件中心是模型网关内的一个左右分栏容器（`src/js/pages/openai/OpenAIPluginsPanel.jsx`），本身不承载业务逻辑：

- **注册表**：`OpenAIPluginsPanel.jsx` 顶部 `PLUGINS` 数组，每项 `{ id, name, description, icon, detail }`。新增插件只需向数组追加一项，无需改动其它文件。
- **布局**：左侧插件列表 + 右侧插件详情，左右 `grid-cols-2` 等宽（1:1）。点击左侧插件切换右侧详情，右侧常驻，不再有「进入/返回」切换。
- **卡片字段**：`name`（主标题）、`description`（副标题，最多 2 行）、`icon`（图标组件，显示在左侧 icon 盒）。
- **入口 Tab**：`OpenAIPage.jsx` 的插件 Tab 只渲染 `<OpenAIPluginsPanel />`，具体模块由面板内左侧卡片决定。
- **后端约定**：插件自己的路由以独立前缀注册进 Go 路由清单（`backend-go/internal/manifest/manifest.go`）与 `server.go` 的 `ServeHTTP` 分派；插件 Service 由 `server.go` 组装并可通过注入接口（如 `SetProxyPoolSelector`）复用其它模块能力。

## 详情组件约定

- `detail` 组件**不接收 `onBack`**，也不再渲染「返回插件中心」按钮（右侧常驻，无返回语义）。
- 详情顶部工具栏只放右侧操作按钮（保存设置等），用 `flex items-center justify-end` 右对齐。
- 详情内部**单列**排布（`flex flex-col gap-3`），多张 `SectionCard` 自上而下堆叠；不要再用两列 grid。
- 属整页滚动页面：详情根与面板不设内部 `overflow-y-auto`，卡片自然高随页滚动。

## 配置卡片（SectionCard + FieldRow）

- 配置区使用 `SectionCard`，`title` 为分组名，`icon` 传 `components/Icons.jsx` 里的图标（如 `Globe`、`Settings`）。
- 必须 `bodyPadding="none"`，行间分隔由内部 `FieldRow` 自带的边框负责（对齐 SettingsPage 规范）。
- 每个配置项使用 `FieldRow title={...}`：`title` 传入 **`<span title={desc}>{label}</span>`** —— 说明文字不直接展示，而是悬浮在标签上显示：

```jsx
const field = (label, desc, control) => (
  <FieldRow title={<span title={desc}>{label}</span>}>
    {control}
  </FieldRow>
);
```

- 控件：开关用 `Switch`，下拉用 `Select`（含 `<Select.Option value="">不使用</Select.Option>` 兜底），数字用 `Input type="number"`（`className="w-24 text-right font-mono"`）。
- 数字字段统一走 `numberField(key, label, desc, min, max)` 小助手，`parseInt` 取值、非法输入置 0。

## 列表（LayerCard + Table）

- 列表包在 `LayerCard className="min-w-0 p-0 shadow-none"` 内，无卡片标题（表头即标题）。
- `Table layout="fixed"` + `text-xs`；`Table.Header variant="compact"`，行 `h-8`；正文行 `h-9`。
- **表头批量开关**：首列表头放一个居中的 `Switch`，控制「全选/全不选」，`title` 说明当前状态与点击效果；行内每行同列再放一个 `Switch`。
- 空态用 `EmptyState title="暂无 X" description="..."`。
- 单元格文本：模型名等用 `font-mono text-[0.8em]`，标题用 `text-kumo-strong`，次要用 `text-kumo-subtle`。

## 弹窗（Dialog）

- 编辑弹窗用 Kumo `Dialog`，固定模板：

```jsx
<Dialog.Root open={open} onOpenChange={setOpen}>
  <Dialog className="flex max-h-[min(calc(100dvh-2rem),44rem)] !w-[min(46rem,calc(100vw-2rem))] !max-w-[min(46rem,calc(100vw-2rem))] flex-col overflow-hidden !p-0">
    <div className="shrink-0 px-6 pt-5">
      <Dialog.Title className="mb-1 text-sm font-semibold text-kumo-strong">标题</Dialog.Title>
      <Dialog.Description className="mb-4 text-sm text-kumo-subtle">说明</Dialog.Description>
    </div>
    <div className="min-h-0 flex-1 overflow-y-auto px-6 py-3 scrollbar-thin">表单</div>
    <div className="flex shrink-0 items-center justify-end gap-3 border-t border-kumo-line px-6 py-4">
      <Dialog.Close render={props => <Button size="sm" variant="secondary" {...props}>取消</Button>} />
      <Button size="sm" variant="primary" onClick={save}>保存</Button>
    </div>
  </Dialog>
</Dialog.Root>
```

## 数据与网络

- 请求统一 `fetch(API, { headers: getAuthHeaders() })`，`getAuthHeaders` 从 `src/js/pages/openai/utils.js` 引入。
- 写操作（POST/PUT/DELETE）完成后需回读验证（列表/详情 GET）确认真实生效。
- 提示用 `src/js/modules/toast.js` 的 `toast.success / toast.error / toast.warning`。

## 代理池复用

独立「代理池」插件（`src/js/pages/openai/plugins/ProxyPoolPlugin.jsx`，后端 `backend-go/internal/proxypool/`）提供可复用出口：

- 前端：插件内 `fetch('/api/proxypool')` 拉池列表，用 `Select` 选 `proxyPoolId`。
- 后端：Service 通过注入的 `ProxyPoolSelector`（`SelectProxy(ctx, poolID, sessionKey)`）按请求轮询出口，共享冷却/429/沉淀禁用状态；`ReportResult` 用于转发结果回写健康数据。
- 优先级约定（见 `backend-go/internal/openaibeta/relay_client.go` 历史实现）：手动代理列表 > 独立代理池 > 网关端点代理池。

## 样式红线

- 只用 Kumo 组件 + 本文模板；不引入页面内散落的硬编码颜色（对照 `docs/重构验证与例外清单.md`）。
- 不在页面里写说明性正文段落；描述一律走 `title` 悬浮。
- 删除/危险操作使用 Kumo `DeleteResource` 或标准 confirm。
- hover 颜色变化即时生效，不用 `transition-colors` / `duration-*`。
- 卡片不用 `border + shadow` 组合，用 `ring ring-kumo-line`；双栏 grid 加 `items-start` 防卡片等高拉伸。

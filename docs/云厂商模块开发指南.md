# 云厂商模块开发指南

最后更新：2026-09-07

本指南沉淀自华为云模块（`huawei`）从零到完整交付的实操过程，用于后续新增云厂商或同类业务模块时快速复制。覆盖**调研 → 文档 → 后端 → 数据库 → 前端 → 治理验证**全链路，并附踩坑清单。

与《新模块接入指南》的关系：后者是通用接入清单（Kumo 约束、路由注册、验收），本文是**带实例与模板的实操手册**，二者互补。开发前先读 [新模块接入指南](./新模块接入指南.md)、[Kumo UI 规则](./Kumo%20UI%20规则.md)、[语义化表格布局与移动端适配](./prd/语义化表格布局与移动端适配.md)、[前端开发最佳实践](./前端开发最佳实践.md)。

## 1. 总览：标准开发流程

```text
前置调研（确定性确认，不猜）
  → ADR（架构决策）+ PRD（含前后端与数据库全设计）
  → 后端骨架（internal/<module>/ + manifest/server 接线）
  → 数据库 schema + 列迁移
  → 前端页面 + 接线（store/MainLayout/Icons）
  → 治理验证（go build/test、lint、governance、route inventory）
  → 真实凭证端到端实测 + 补单测锁死解析
```

## 2. 前置调研：用「确定」代替「猜」

这是本项目最关键的教训。接口/能力是否可用，只用两条证据链判定，不靠文档猜测：

### 2.1 官方文档声明
- 目标厂商的官方 API 概览页逐条声明「某操作所用接口为 XX 服务的 YY 接口」（如华为云 `api-flexusl` 明确 Flexus L 列表走配置审计 RMS、云主机操作走 ECS）。
- 官方明确写「没有对应的 API」的能力（如 Flexus L 远程登录无 API）即为确定不可用，不再深挖。
- 文档页若是 SPA 壳（curl 只拿到 4KB 框架），正文用正则从 HTML 剥文本，或从官方 SDK 元数据拿契约。

### 2.2 SDK 元数据（代码生成，100% 确定）
- 官方 Go SDK（如 `huaweicloud-sdk-go-v3`）由 OpenAPI 生成，**method/path/请求响应模型字段**即真实契约：
  - `core/auth/signer/signer.go`：签名算法精确规则（canonicalURI 尾斜杠、contentHash、SK 直接签名）。
  - `services/<svc>/v2/<svc>_meta.go`：`GenReqDefForXxx` 的 `WithMethod/WithPath/WithName/WithLocationType` 给出路径与参数。
  - `services/<svc>/v2/model/model_*.go` 的 `json:"..."` tag 给出请求/响应字段（如 `OrderInstanceV2.expire_time`）。

### 2.3 探针实测（最硬证据）
- 用测试凭证写一次性签名脚本，对候选接口逐个实调：
  - `2xx` → 可用并记录返回结构。
  - `404 APIGW.0101` → 接口未发布（该区域/该 AK 环境），跳过。
  - `403` → 权限不足。
- 写操作（启停/删除/重置）会真实影响资源，实调前必须用户授权，或用非业务实例。
- 实测同时确认**域名后缀**（国内站 `myhuaweicloud.cn` vs 国际站 `myhuaweicloud.com`）、**区域端点**（服务级 vs 全局级）、**分页参数**（marker/limit vs offset/limit）。

## 3. 文档先行

### 3.1 ADR（决策）
参照 `docs/adr/0002-GCP模块架构决策.md` / `0003-华为云模块架构决策.md` 的格式，至少决策：
- REST 自研 vs 官方 SDK（低依赖定位优先 REST + 自研签名；签名复杂度高才考虑 SDK，如 Oracle）。
- 凭证模型与加密策略（敏感字段 `secure.SecureEncrypt` 加密落库，标识字段明文）。
- 站点/区域上下文如何承载。
- 组合产品（如轻量服务器）跨服务接入策略。
- 异步操作语义（指令已下发 vs 资源已变更）。
- 与现有模块边界、Range 划分。

### 3.2 PRD（前后端+数据库全设计）
参照 `docs/prd/HuaweiCloud模块PRD.md`，至少包含：
- Problem/Goals/Non-Goals、User Stories、Product Scope（Phase 划分）。
- **Functional Requirements**：逐资源域（账号/计算/DNS/网络/存储/费用）列接口、字段、动作规则。
- **UX Requirements + 前端设计细节**：Tabs、表格列（AppTable 语义角色）、选择器、间距、空/载/错态、删除确认、移动端。
- **数据库设计**：表名、完整 DDL、字段说明表、索引、幂等迁移。
- **后端技术设计**：模块目录、client/签名、account_store 脱敏、路由段数、聚合策略。
- API Contract（完整路由清单）、Security、Observability、Testing、Release Plan、Acceptance Criteria、Risks、Out of Scope。

## 4. 后端开发

### 4.1 模块目录（照 GCP/Oracle/huawei 模板）

```text
backend-go/internal/<module>/
├── service.go          # Service + New + ServeHTTP 分发 + open()
├── schema.go           # 建表 + 列迁移（幂等）
├── account_store.go    # 账号 CRUD + secure 加密 + safeAccount 脱敏
├── types.go            # Account / payload / Normalized* 响应结构
├── client.go           # 统一 REST 封装 + base URL 映射 + 分页
├── auth.go             # 签名器（SDK-HMAC-SHA256 / OAuth2 JWT 等）
├── <resource>_service.go  # 按资源域拆分（compute/dns/network/storage/billing…）
├── ssh.go              # WebSocket→SSH 终端桥接（如需面板内终端）
└── service_test.go     # 签名、schema、归一化解析单测
```

### 4.2 Service 与路由分发

- `New(cfg)`：`database.New(cfg)` + 5s 超时 `open()` 预检建表（失败仅 warn）。
- `ServeHTTP`：`strings.TrimPrefix(path, "/api/<module>")` → Trim → Split，按「段数 + 首段 + Method」switch。
  - **段数陷阱**：`/accounts/{id}/projects/{pid}/buckets` 是 **5 段**（index 0-4），不是 6。含深路径时逐级核对 Split 结果，写反会导致本地 404。
  - 含斜杠的动态段（对象名）用 `r.URL.EscapedPath()` 切分再逐段 `url.PathUnescape`。
- handler 骨架：`accountForRequest`（取账号）→ `clientForAccount`（解密凭证构造 client）→ domain 方法 → `response.OK/Error`。

### 4.3 数据库

#### 建表 + 列迁移（幂等）
参照 `huawei/schema.go`：
- 首批 `CREATE TABLE IF NOT EXISTS` + 索引。
- 旧表加列用第二批迁移：`PRAGMA table_info(<table>)` 检查列是否存在（`hasColumn`），不存在才 `ALTER TABLE ... ADD COLUMN`。
- 依赖新列的索引必须在迁移完成后创建。

#### 账号表通用模式
```sql
CREATE TABLE IF NOT EXISTS <module>_accounts (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL,
    <标识字段> TEXT NOT NULL,          -- 明文（AK/OCID/email），列表脱敏展示
    <敏感凭证>_encrypted TEXT NOT NULL, -- secure.SecureEncrypt
    <可选敏感字段>_encrypted TEXT,       -- 如 SSH 私钥/密码，空存 NULL
    <上下文字段> TEXT,                   -- default_region / default_project_id 等
    description TEXT,
    last_verified_at DATETIME,
    last_verify_status TEXT,
    last_verify_error TEXT,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

#### account_store 约定
- 加工链：`cleanAccountPayload`（TrimSpace）→ `validateAccountPayload`（必填）→ 敏感字段 `secure.SecureEncrypt` → 空值 `nullEmpty` 存 NULL。
- `scanAccount` 解密明文入内存（`json:"-"` 不回显）；列表响应 `safeAccount` 脱敏（标识掩码 + `hasXxx` 布尔），绝不回显凭证。
- 更新「留空不覆盖」：字段空则回填当前值；敏感字段留空不更换密钥。
- 导出/导入：`/export/accounts`（GET 明文导出）、`/import/accounts`（POST 事务 + `upsertImportedAccount` 按唯一键查重 upsert，可选 overwrite 清空全表）——照 `oracle` 模式。

### 4.4 REST client + 签名

- `client.do(ctx, service, method, path, query, body, out)`：拼 URL、签名、超时（30s）、响应限流（8MB）、错误提取。
- base URL 映射表支持环境变量逐服务覆盖（`HUAWEI_<SERVICE>_API_BASE_URL`），测试指向 mock。
- 独立签名协议（如 OBS 不走主签名）单独一个 `obs_auth.go`。
- **华为云 SDK-HMAC-SHA256 三坑**（对照官方 signer 源码）：
  1. canonicalURI 强制尾斜杠**仅用于签名**，实际请求 URL 用原始路径。
  2. canonicalRequest 含第 6 段 contentHash（JSON body 的 sha256，空 body 为 `e3b0c442…`）。
  3. 签名 key 直接用 SK（无 AWS 派生链）。
- 聚合（"all" 模式）：并发遍历项目/区域，**跳过失败区域只返回成功部分**，全部失败才报错；单区域请求加独立超时（8s）避免最慢区域拖垮整体；失败区域写日志便于定位。参照 `aggregateProjects[T]` 泛型 helper。

### 4.5 manifest / server 接线（4 处 + 1 行）

- `manifest.go`：`{Prefix: "/api/<module>", Module: "<module>", Owner: OwnerGo, Auth: AuthSession, ResponseMode: ResponseJSON, Description: "…"}`
- `server.go`：import、Server 结构体字段、`newServer()` 实例化、`serveGoRoute()` case 四处。

### 4.6 WebSocket 终端（如需面板内 SSH）

- 复用 `x/crypto/ssh`（已在 go.mod）+ `gorilla/websocket`。
- 桥接模式参照 `serveragent/terminal_ws.go` / `huawei/ssh.go`：WebSocket 升级 → 取账号 → SSH 直连（key 优先/密码兜底）→ PTY → 双向桥接（input/resize/data/error 消息协议）+ 心跳。
- 账号表存 SSH 凭据（`ssh_user/ssh_port/ssh_private_key_encrypted/ssh_password_encrypted`），连接目标 = 实例公网 IP。

## 5. 前端开发

### 5.1 接线（3 文件 + 页面）

- `store.js`：`MODULE_CONFIG` 加条目 + `MODULE_GROUPS` 的 `cloud-vendors.modules` 数组加 key（**顺序即侧边栏顺序**，按用户期望排序）。
- `MainLayout.jsx`：lazy import + `renderActivePage()` case + `stickyHeaderScrollModule` 数组（决定整页滚动模式）。
- `Icons.jsx`：`MODULE_ICON_MAP` 品牌图标（暂无就 `Cloud` 兜底，品牌色属允许例外）。
- 路由路径 = 模块 ID。

### 5.2 页面结构（Kumo-only + AppTable 语义列）

- 根容器 `<PageStack>` + sticky tab 栏（`stickyTabsBaseClass` + `MODULE_TABS_PROPS`），资源视图头部放账号/项目选择器 + 刷新。
- **表格必须用 `AppTable tableId=... columns=[...]` + children 手写 `Table.Header/Head/Body/Row/Cell`**；列用语义角色（`primary/status/datetime/meta/identifier/number/actions-*`），AppTable 自动生成 colgroup。每个表格至少一个弹性列（primary/content/identifier）。
- 空/载/错态：加载用 AppTable 骨架行（`SkeletonLine`），空用 `EmptyState card={false}`（避免卡片套边框），失败 `toast.error`。
- 删除确认 `dialog.deleteResource`；操作按钮按状态显隐；文字按钮同排超 3 个时改图标按钮（`shape="square"`）并让操作列用足够宽度。

### 5.3 Kumo 组件正确用法（踩坑实录）

- **Dialog 必须包在 `Dialog.Root` 内**，内容用 `<Dialog>` + `Dialog.Title/Description`（裸 `<Dialog open>` 会报 `useDialogRootContext undefined`）。
- Kumo `Select` 用 `items`（不是 `options`）+ `aria-label`（不是 `label`）。
- Kumo `Table` 表头子组件是 `Table.Head`（不是 `Table.HeaderCell`，会报 "Element type is invalid"）。
- `Button variant` 合法值：`primary/secondary/ghost/destructive/secondary-destructive/outline`，**没有 `danger`**。
- 文本多行输入用 `Textarea`（从 `@cloudflare/kumo/components/input` 导出）。

### 5.4 布局规范（README 踩坑重点）

- 表格型 `SectionCard` 必须 `bodyPadding="none"`，否则四边留白。
- 表格页面走**整页滚动 + tab 吸附**，不要 `min-h-0 flex-1 overflow-auto` 内部滚动壳（见 docs/README 第 51/58 条）。
- 卡片内容不等高用 `items-start`；瀑布流用 `columns-1 gap-3 cq-md:columns-2 [&>*]:mb-3 [&>*]:break-inside-avoid`。
- 顶部操作收进 sticky tab 栏（`Select`/刷新按钮），随 Tab 显隐。

### 5.5 高频功能模板

- **详情/操作 Dialog**：`Dialog.Root open={Boolean(x)} onOpenChange` + `KeyValueGrid` 明细 + 操作按钮组。
- **终端**：`SSHTerminalDialog`（`@xterm/xterm` + FitAddon + WebSocket），复用 `huawei/SSHTerminalDialog.jsx`。
- **导入导出**：标题栏 `Download/Upload` 按钮 + 导入 Dialog（`Textarea` 粘贴 JSON + `Switch` 覆盖），提交 `POST /import/accounts`。

## 6. 治理与验证

```bash
go build ./... && go vet ./internal/<module>/... && go test -count=1 ./internal/<module>/...
npm run lint
npm run governance:check          # manifest 路由治理（既有非本模块 warning 可忽略）
node tools/backend-route-inventory.mjs   # 确认 /api/<module> 入册
npm run backend-go:test
```

- 归一化解析（把厂商「字符串整数」等怪异类型转正）必须写**单测锁死**：直接喂厂商真实响应结构的 fixture，断言关键字段解析成功（参照 `TestNormalizeInstanceShowServer`）。
- 真机端到端：测试凭证对每个 Phase 1 接口实调；能实调的不靠猜。

## 7. 踩坑清单（本次教训汇总）

1. **厂商响应里的「字符串整数」**：如 `flavor.disk/vcpus/ram`、`addresses[].version` 返回 `"2"` 而非 `2`，Go `int` 反序列化直接失败并静默吞掉整个解析。用 `flexInt64`（兼容字符串/数字的 `int64`）兜底。
2. **路由段数偏移**：`/accounts/{id}/projects/{pid}/buckets` 是 5 段，写成 6 即本地 404（1ms）。
3. **聚合误报 502**：`len(all)==0 && errs>0` 会把「成功但空列表」误判为全失败。按**成功区域数**判断（`successCount==0` 才报错）。
4. **Kumo Dialog/Select/Table/Button 用法**见 5.3。
5. **弹窗超高**：核心表单与可选配置（如 SSH 凭据）分开成独立 Dialog，避免一个弹窗内容溢出。
6. **到期时间来源**：流量包 `end_time` 是**当月流量周期**，不是套餐到期；包周期到期走 BSS「查询客户包年/包月资源」（`POST /v2/orders/suscriptions/resources/query`，注意官方拼写 `suscriptions`）。
7. **无效区域项目**（如自定义项目名 `MOS`）：会拼出不可解析域名，聚合跳过 + 日志即可。
8. **VNC 等控制台专用能力**：客户 AK/SK 实调 404 即为平台不开放，官方文档「无对应 API」双重确认后放弃，改用 Web SSH。

## 9. API 接口目录全面接入（防止只接前缀）

### 为什么必须做
manifest 只登记模块前缀（无子路由）时，接口会退化成「基础」分组孤零零一行，且被 MCP 接口目录标为 `prefixRoute`（聚合前缀、不可直接调用），`find_api` 按意图几乎召回不到。华为云、GCP 都因此漏了很久。**只做 manifest 前缀 ≠ 已接入**。

### 全面接入清单（6 处）
| # | 文件 | 内容 |
|---|---|---|
| 1 | `backend-go/internal/manifest/manifest.go` | 前缀一行 + 逐条子路由（`MatchExact`/`MatchPattern`），从模块 `ServeHTTP` 分发照抄 |
| 2 | `backend-go/internal/system/route_descriptions.go` | 每条路由的中文描述（影响 find_api 召回） |
| 3 | `backend-go/internal/system/api_docs_catalog.go` | `apiDocSeeds` 逐条登记（**写接口必须显式 `Methods`**，否则 infer 默认 GET） |
| 4 | `backend-go/internal/system/route_aliases.go` | 模块名 + 关键资源的别名组（口语→路由） |
| 5 | `backend-go/internal/system/route_contracts.go` | 每个写接口的请求体 schema（`obj`/`noBody`）；**缺了会被契约覆盖测试强制失败** |
| 6 | 分组（2 处） | 后端 `system/service.go` `routeGroup()` 加前缀分支；前端 `ApiDocsPage.jsx` 的 `routeGroup()`、`GROUP_ORDER`、`GROUP_NAME_TO_MODULE_ID`、`MODULE_LABELS` 四处 |

### 校验
```bash
go test -count=1 ./internal/system/...   # 含「写接口缺少请求契约」强制审计
npm run governance:check                 # manifest 路由治理
node tools/backend-route-inventory.mjs   # 确认子路由入册
```
浏览器：API 接口页应能看到独立分组的完整子路由，MCP `list_apis` 不再标该模块为孤立 prefixRoute。

### 自动 / 手动两条路径
- **自动（推荐）**：运行 `node tools/gen-api-catalog.mjs <module>`，脚本从 manifest.go 提取该模块子路由，自动生成第 1/2/3/5 项的 Go 骨架（写接口方法标注 TODO，请求体用 `noBody` 占位），再人工补中文描述与请求体字段。第 6 项分组由脚本输出接线提示。
- **手动**：按上表 6 项逐条登记（华为云、GCP 即为手动完成，可用作参考样例）。
- 演进建议：后续可把「目录覆盖审计」纳入 governance：manifest 有 `MatchPattern` 子路由的模块，若在 `apiDocSeeds` 无对应登记则告警，从源头兜底。

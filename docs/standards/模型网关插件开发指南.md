# 模型网关插件中心开发指南

最后更新：2026-09-15

本文档沉淀「模型网关 → 插件中心」的插件结构、样式约定与可复用模式，供后续新增插件直接套用。
内容分两层：**通用骨架**（任何插件都要遵守）与**进阶模式**（多账号、多区域等场景按需取用）。

## 插件中心机制

插件中心是模型网关内的一个左右分栏容器（`src/js/pages/openai/OpenAIPluginsPanel.jsx`），本身不承载业务逻辑：

- **注册表**：`OpenAIPluginsPanel.jsx` 顶部 `PLUGINS` 数组，每项 `{ id, name, description, icon, detail }`。新增插件只需向数组追加一项，无需改动其它文件。
- **布局**：左侧插件列表 + 右侧插件详情，点击左侧切换，右侧常驻。
- **卡片字段**：`name`（主标题）、`description`（副标题，最多 2 行）、`icon`（图标组件）。
- **入口 Tab**：`OpenAIPage.jsx` 的插件 Tab 只渲染 `<OpenAIPluginsPanel />`。
- **后端约定**：插件路由以独立前缀注册进 `backend-go/internal/manifest/manifest.go` 与
  `server.go` 的 `ServeHTTP` 分派；插件 Service 由 `server.go` 组装，可通过注入接口复用其它模块能力。

## 插件登记与清单

- **安装记录**：`docs/plugins/registry.json` 是插件登记的**唯一事实来源**，逐项记录后端目录、manifest 行、
  `server.go` 接线（import / 字段 / 构造 / 注入 / serve case / 鉴权分支）、建表、前端文件与注册点、
  外部依赖、卸载步骤。新增插件必须追加一条，卸载时按 `uninstallSteps` 逐项回滚。
- **单插件设计文档**（registry 摘要不够用时）放 `docs/standards/` 下，命名 `模型网关插件-<id>方案.md`。
- **接线自检**：改完接线后跑 `npm run governance:check`（校验 manifest 与 `server.go` 的 `case` 是否
  对得上、前端路由字面量是否被 manifest 覆盖）与 `npm run ui:governance`、`npx eslint <改动文件>`。

## 一、后端通用骨架

### 1.1 目录与文件划分

```
backend-go/internal/<plugin>/
├── service.go    Settings/Account、加密落库、选号、冷却、调用计数
├── handlers.go   管理面 HTTP 接口
├── link.go       网关端点接入（接入/断开/状态）
├── relay.go      中继面：请求转发、换号重试
├── upstream.go   上游协议层（URL 构造、请求/响应、错误分类）
└── service_test.go
```

按职责拆分而非按接口拆：上游协议事实集中在 `upstream.go`，其余文件只做本地编排。
若上游协议复杂（需要签名、协议转换、流式改写），再加 `upstream_*.go` 或独立 `engine/` 子包。

### 1.2 配置持久化：单行加密 JSON

不要为每个字段建列，整份设置序列化成一行加密 JSON：

```sql
CREATE TABLE IF NOT EXISTS <plugin>_settings (
    id INTEGER PRIMARY KEY CHECK (id = 1),
    data TEXT NOT NULL            -- secure.EncryptJSON(Settings)
);
```

- 读取用 `secure.IsEncrypted` 判断，**兼容存量明文行并原地迁移为密文**。
- `Settings` 内的切片字段在 `normalizeSettings` 里补空值，避免旧行留下 `nil`。
- 凭据（token 等）随 `Settings` 一起加密，不单独建表。

调用计数单独一张表，用「内存增量 + 定期落盘」避免每请求写库：

```sql
CREATE TABLE IF NOT EXISTS <plugin>_call_stats (
    identifier TEXT PRIMARY KEY,
    count INTEGER NOT NULL DEFAULT 0
);
```

内存里维护 `callBase`（已落盘基线）+ `callPending`（未落盘增量），
`callDisplay = base + pending`；落盘用 `INSERT ... ON CONFLICT DO UPDATE SET count = count + excluded.count`，
失败时把增量放回等待下轮重试。

### 1.3 设置读写的不对称（重要）

`PUT /settings` **不接受**前端回传的「由专用接口持有的字段」与「不下发前端的字段」，
由后端用当前值覆盖：

```go
current := s.Settings()
body.Accounts = current.Accounts              // 含凭据，不下发前端；回传的必然是脱敏数据
body.DisabledModels = current.DisabledModels  // 由 toggle 专用接口持有
```

原因：前端「保存设置」是整对象 PUT，这两类字段在本地可能是切换前的快照，
接受回传会把刚做的操作覆盖掉（现象：开关存不住）。

### 1.4 账号脱敏

凭据类数据一律经 `toAccountView` 转成视图再下发，视图里**不含任何 token**，只给状态：

```
tokenState    valid / expiring / expired / unknown
available     综合判据（未停用 + 有凭据 + 未过期）
scopeReady    凭据的 scope 是否满足查询额度的前提
lastError     最近一次失败原因，供排障
```

前端的状态徽标与后端的选择逻辑必须用**同一判据**（都走 `accountAvailable`），
否则会出现「前端显示可用但实际不被选中」这类不一致。

### 1.5 账号导入导出（标配能力）

多账号插件都应提供导入导出，用于迁移与备份。**所有插件的接口与文件形状保持一致**，
便于跨插件复用与人工搬运：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/accounts/export` | 下载 JSON（`Content-Disposition: attachment`），含 token |
| POST | `/accounts/import` | 按 ID 去重合并，**已存在则保留本机版本** |

导出文件形状：

```json
{ "version": 1, "exportedAt": "<RFC3339>", "accounts": [ ... ] }
```

导入要**同时接受两种形状**：上述包装对象与裸数组 `[...]`。

```go
func decodeImportBody(r *http.Request) ([]Account, error) {
    var probe json.RawMessage
    if err := json.NewDecoder(r.Body).Decode(&probe); err != nil {
        return nil, fmt.Errorf("请求体解析失败")
    }
    trimmed := strings.TrimSpace(string(probe))
    if trimmed == "" {
        return nil, fmt.Errorf("请求体为空")
    }
    if strings.HasPrefix(trimmed, "[") {
        var arr []Account
        if err := json.Unmarshal(probe, &arr); err != nil {
            return nil, fmt.Errorf("账号解析失败: %w", err)
        }
        return arr, nil
    }
    var wrapper exportPayload
    if err := json.Unmarshal(probe, &wrapper); err != nil {
        return nil, fmt.Errorf("配置解析失败: %w", err)
    }
    return wrapper.Accounts, nil
}
```

**导入时的字段补齐**（避免导入后账号不可用）：

- `ID` 为空时用 `email` 或 `projectId` 兜底；
- 缺 `accessToken` 的条目直接跳过；
- `region` 为空时补当前全局区域（多区插件）；
- `createdAt` 为空时补当前时间；
- `expiresAt` 为负值时归零（首次转发会触发 refresh 续期）。

**前端**：用 `Toolbar` 放两个按钮（导出 / 导入），导入走隐藏 `<input type="file">`：

```jsx
<Toolbar size="sm" aria-label="账号导出导入" className="shrink-0">
  <Toolbar.Button onClick={() => window.open(`${API}/accounts/export`, '_blank')} icon={<Upload className="h-3.5 w-3.5" />}>
    <span className="hidden cq-sm:inline">导出</span>
  </Toolbar.Button>
  <Toolbar.Button onClick={() => fileInputRef.current?.click()} icon={<Download className="h-3.5 w-3.5" />}>
    <span className="hidden cq-sm:inline">导入</span>
  </Toolbar.Button>
</Toolbar>
<input ref={fileInputRef} type="file" accept=".json,application/json" className="hidden"
  onChange={e => { importFile(e.target.files?.[0]); e.target.value = ''; }} />
```

导入完成后要**重新拉取账号与状态**：`await Promise.all([loadAccounts(), loadStatus()])`。

## 二、前端通用骨架

### 2.1 详情组件约定

- `detail` 组件**不接收 `onBack`**（右侧常驻，无返回语义）。
- 顶部工具栏只放右侧操作按钮，`flex items-center justify-end`。
- 内部**单列**排布（`flex flex-col gap-3`），多张 `SectionCard` 自上而下堆叠。
- 属整页滚动页面，不设内部 `overflow-y-auto`，卡片自然高随页滚动。

### 2.2 配置卡片（SectionCard + FieldRow）

- `SectionCard` 必须 `bodyPadding="none"`，行间分隔由 `FieldRow` 自带边框负责。
- 说明文字不直接展示，走 `title` 悬浮：

```jsx
const field = (label, desc, control) => (
  <FieldRow title={<span title={desc}>{label}</span>}>
    {control}
  </FieldRow>
);
```

- 控件：开关 `Switch`、下拉 `Select`、数字 `Input type="number" className="w-24 text-right font-mono"`。

### 2.3 列表（LayerCard + Table）

**必须两层结构**，只写滚动容器会导致表格没有边框、与相邻卡片视觉不一致：

```jsx
<LayerCard className="min-w-0 overflow-hidden p-0 shadow-none">
  <div className="min-w-0 overflow-x-auto overscroll-x-contain scrollbar-thin">
    <Table layout="fixed" className="w-full min-w-[42rem] text-xs">
      <Table.Header sticky variant="compact">
        <Table.Row className="h-8">
          <Table.Head className="!px-2.5 !py-1.5">列名</Table.Head>
        </Table.Row>
      </Table.Header>
      <Table.Body>{/* 行高 h-9 ~ h-12 */}</Table.Body>
    </Table>
  </div>
</LayerCard>
```

- **不要嵌套表格**。多组信息用「加列」表达，内嵌子表会挤压列宽、破坏层级一致性。
- 表头批量开关：首列表头放居中 `Switch` 控制全选，`title` 说明当前状态与点击效果。
- 空态用 `EmptyState`；单元格文本层次**靠颜色而非字号**：
  `text-kumo-strong`（主）、`text-kumo-subtle`（次）、`font-mono`（标识符等宽）。
- **禁止在表格单元格内叠加 `text-[0.8em]` 这类字号缩放**（详见 2.7）。
- **同一行内数值列字号必须一致**，混用会让某一列显得突兀。

### 2.4 字号：不要在组件内再缩放（重要）

Kumo 组件自带字号，再叠加缩放会**两级缩小**：

| 场景 | 组件自带 | 叠加后 | 结果 |
| --- | --- | --- | --- |
| `Badge` + `!text-[0.8em]` | `text-xs`（12px） | 9.6px | 过小 |
| `Table text-xs` + `text-[0.8em]` | 12px | 9.6px | 过小 |

多行时行密度一致，视觉上是「紧凑表格」；**只有一行时没有其他行作参照，小字号单独暴露，显得格外小**。

**约定**：

- 表格与 `Badge` 内**不再叠加任何 `text-[0.8em]` / `text-[0.75em]`**；
  层次改由颜色（`kumo-strong` / `kumo-subtle`）+ `font-mono` 承担。
- 需要局部略小时用 `text-[0.85em]` 起步，不要用 `0.8em` 以下。
- `Badge` 显式写 `className="text-xs"`（与组件默认一致，便于后续统一调整）。
- **例外**：弹窗内的 URL 链接、授权链接输入框、统计卡片内的 `text-[10px]` 标签
  不属表格单元格，维持原状（改动会破坏其所在布局）。

### 2.5 进度条（Meter）

用 Kumo `Meter` 的**原生渲染**，不要在外面手搭数值行 + 裸进度条：

```jsx
<Meter
  label="$19.78 / $20.00"        // 渲染在轨道上方
  value={pct}
  max={100}
  customValue="98.9%"            // 渲染在右侧
  trackClassName="!h-1 bg-kumo-recessed"
  indicatorClassName={tone}
/>
```

阈值着色用 `bg-kumo-danger` / `bg-kumo-warning` / `bg-kumo-success`。
配额类指标展示**剩余**比展示已用更符合直觉（尤其周期重置型额度）。

### 2.6 弹窗与浮层（Dialog / Popover）

**选择原则**：

| 场景 | 用 |
| --- | --- |
| 表单编辑、需要用户专注完成的多步操作 | `Dialog` |
| 查看明细、只读信息、从某一行就地展开 | `Popover` |

Popover 贴在触发位置、点击别处自动关闭，交互成本比「开弹窗 → 看完 → 关闭」少一步，
**只读明细优先用 Popover**。

Dialog 模板：

```jsx
<Dialog.Root open={open} onOpenChange={setOpen}>
  <Dialog className="flex max-h-[min(calc(100dvh-2rem),44rem)] !w-[min(46rem,calc(100vw-2rem))] !max-w-[min(46rem,calc(100vw-2rem))] flex-col overflow-hidden !p-0">
    <div className="shrink-0 px-6 pt-5">
      <Dialog.Title className="mb-1 text-sm font-semibold text-kumo-strong">标题</Dialog.Title>
      <Dialog.Description className="mb-4 text-sm text-kumo-subtle">说明</Dialog.Description>
    </div>
    <div className="min-h-0 flex-1 overflow-y-auto px-6 py-3 scrollbar-thin">表单</div>
    <div className="flex shrink-0 items-center justify-end gap-3 border-t border-kumo-line px-6 py-4">
      <Dialog.Close render={props => <Button size="sm" variant="secondary" {...props}>取消</Button>} />
      <Button size="sm" variant="primary" onClick={save}>保存</Button>
    </div>
  </Dialog>
</Dialog.Root>
```

Popover 模板（受控，用于「点某行数据看明细」）：

```jsx
<Popover
  open={activeRow?.id === row.id}
  onOpenChange={open => {
    if (open) loadDetail(row);
    else if (activeRow?.id === row.id) setActiveRow(null);
  }}
>
  <Popover.Trigger
    nativeButton={false}
    render={
      <Button type="button" size="sm" variant="ghost"
        className="font-mono text-xs focus:outline-none focus:ring-0 focus-visible:outline-none focus-visible:ring-0">
        {row.value}
      </Button>
    }
  />
  <Popover.Content side="bottom" align="center"
    className="w-80 shrink-0 px-3 pb-2 pt-2.5 max-h-[min(70vh,28rem)] overflow-y-auto overscroll-contain scrollbar-thin">
    {/* 顶部：标题 + 合计；中间：divide-y 列表；底部：border-t + 说明 */}
  </Popover.Content>
</Popover>
```

**浮层内加载异步数据必须防竞态**：快速切换行时，前一个请求的响应可能后到并覆盖当前展示。
用请求序号丢弃过期响应：

```jsx
const seqRef = useRef(0);
const loadDetail = async row => {
  const seq = ++seqRef.current;
  setBusy(true);
  try {
    const data = await fetch(...).then(r => r.json());
    if (seq !== seqRef.current) return;   // 已切换到别的行，丢弃
    setDetail(data);
  } finally {
    if (seq === seqRef.current) setBusy(false);
  }
};
```

### 2.7 数据与网络

- 请求统一 `fetch(API, { headers: getAuthHeaders() })`，从 `src/js/pages/openai/utils.js` 引入。
- 写操作（POST/PUT/DELETE）完成后**回读验证**（列表/详情 GET）确认真实生效。
- 提示用 `src/js/modules/toast.js` 的 `toast.success / toast.error / toast.warning`。

### 2.8 批量开关的位置

模型的批量启用/停用**只保留表头首列的 `Switch`**（全选/全不选），
不要在卡片 `actions` 里再放「全部启用 / 全部停用」按钮：

- 表头已有开关，重复提供两个入口会造成「同一功能两处控制」的困惑；
- `actions` 位置应留给该卡片**独有的**操作（如「刷新目录」）。

表头开关用 `title` 说明当前状态与点击效果，`aria-label="全选模型"`。

## 三、进阶模式

以下模式在对应场景下按需取用，都是已在生产验证过的实现。

### 3.1 多账号选号策略

三种策略，用 `Settings.AccountStrategy` 切换：

| 值 | 行为 | 适用 |
| --- | --- | --- |
| `first` | 列表首个可用，其余作主备 | 行为最可预期，默认 |
| `round-robin` | 依次轮询 | 账号额度相近 |
| `least-used` | 选剩余额度最多的 | 额度差异大，避免某个先撞上限 |

**硬过滤三件套**（三策略共有）：

```
accountAvailable(a)   → 停用 / 无凭据 / token 已过期 一律排除
tried[a.ID]           → 本次请求已尝试过的排除（避免重试打同一账号）
inCooldown(a.ID)      → 失败冷却中的排除
```

全部冷却时**退回最早恢复的账号**继续尝试 —— 冷却只是软偏好，
不该把一次瞬时抖动放大成整池不可用。

**轮询游标必须用原始列表下标锚定**：

```go
// 错：候选集长度会随冷却/停用变化，取模会回绕导致分配不均
pos := cursor % len(usable)

// 对：始终「从上次位置往后找下一个候选」
chosen := usable[0]
if s.rrInit {
    for _, c := range usable {
        if c.idx > s.rrLastIdx {   // c.idx 是原始列表下标
            chosen = c
            break
        }
    }
}
s.rrLastIdx = chosen.idx
```

反例：3 账号轮询，第 2 个冷却后候选集变 2 个，游标从 2 开始 → `2 % 2 = 0`，
又跳回第一个，导致部分账号被反复选中、另一些被跳过。**此逻辑必须有回归测试把守**。

**额度快照要三处更新**，缺一不可：

1. 用量查询时写回真实额度；
2. 后台定时刷新（仅在 `least-used` 策略下触发，其余策略零开销）；
3. **转发成功后异步刷新**（带单账号节流）—— 只靠定时刷新会让策略退化成 `first`。

失效机制：快照超过 TTL（建议 2 小时）视为无数据按 0 处理，避免基于陈旧值决策。

### 3.2 账号级区域（多区共存）

若上游有多个区域（如 us/eu），区域要存在 `Account` 上而非 `Settings` 全局单值，
否则多区账号无法共存。统一用取值函数（优先账号级、回落全局）：

```go
func (s *Service) accountRegion(acc Account) string {
    if r := normalizeRegion(acc.Region); r != "" {
        return r
    }
    return normalizeRegion(s.Settings().Region)
}
```

**所有 URL 构造都接收账号参数**（网关地址、主站地址、token 刷新、额度查询），
否则跨区账号会打到错误的端点。

### 3.3 上游错误分类与换号

把上游失败归类成可判断的结构，而不是裸 error：

```go
type upstreamError struct {
    status    int
    retryable bool    // 是否换号重试
    rateLimit bool    // 是否限流（可用于更长的冷却）
}
```

分类约定：429 / 5xx / 401 / 403 视为可重试（换号可能有效），其余直接返回。
单请求最多尝试 N 个账号（建议 3），`tried` 去重。

**关键约束**：失败必须在**写出任何响应体之前**返回，否则换号重试会破坏已下发的字节。
流式转发时，一旦开始写就不可重试。

### 3.4 凭据类型选型（接入新上游前的第一步）

不同上游对凭据的要求差异很大，**先用最小探针确认「哪种凭据能过鉴权」再动手写插件**：

- 拿一个必然无效的假 token 打目标端点，观察错误响应；
- 若真实 token 与假 token 的错误**完全一致**，说明该端点不区分「无效」与「无权限」，
  需要换凭据类型或检查 scope；
- 若平台有「服务端权限校验」与「网关权限校验」两套规则，注意二者可能不一致
  （例如服务端放行通配符而网关只认字面量 scope）。

**不要假设 API Key 通用**。常见形态：

| 形态 | 典型前缀 | 适用 |
| --- | --- | --- |
| 可公开的采集 token | `phc_` 类 | 只用于事件上报，不能访问管理/网关接口 |
| 个人 API Key | `phx_` 类 | 访问管理接口，可能需要额外申请 scope |
| OAuth access token | `pha_` 类 | 需授权流程，可拿到特权 scope |

### 3.5 OAuth 的 redirect_uri 必须由服务端固定（重要）

`redirect_uri` 是**上游 OAuth 应用的注册属性**，与面板部署在哪个域名无关。
它必须由后端按注册值固定，**不能由前端按 `window.location.origin` 推导**：

```js
// 错误：面板从 https://panel.example.com 访问时得到
//       https://panel.example.com/callback —— 上游从未注册过该地址
const callbackUri = () => `${window.location.origin}/callback`;
```

典型报错：`invalid_request: Mismatching redirect URI`。

**约定**：

- 后端定义唯一的回调地址来源（常量 + 环境变量覆盖），授权与换码**两处共用**：

```go
const defaultRedirectURI = "http://localhost/callback"
const envRedirectURI = "POSTHOGCODE_REDIRECT_URI"

func callbackRedirectURI() string {
    if v := strings.TrimSpace(os.Getenv(envRedirectURI)); v != "" {
        return v
    }
    return defaultRedirectURI
}
```

- 把 `redirect_uri` **存进 OAuth 会话**，换码时从会话取，不要从用户粘贴的回调地址反推：

```go
type oauthState struct {
    verifier    string
    region      string
    redirectURI string   // 授权时用的值，换码必须完全一致
    createdAt   time.Time
}
```

- 授权与换码的 `redirect_uri` 只要有一个字符不同，token 端点就会以
  `invalid_grant` 拒绝，且错误信息通常不指出是这个字段的问题。

**判断注册值的两个途径**：

1. 上游若提供 Desktop/CLI 客户端，查其源码里硬编码的回调地址；
2. 桌面端应用的常见注册值是 `http://localhost/callback`（无端口）。
   按 RFC 8252 §7.3，`localhost` 允许任意端口，故回环地址可放心使用。

### 3.6 额度的口径陷阱

周期重置型额度要注意三点：

1. **额度是组织级还是账号级** —— 多账号时若各账号属不同组织，额度互相独立，
   前端**不能合并成一行显示**，也不能加总（加总无意义且误导）。
2. **计费周期是每账号独立的** —— 若各账号注册时间不同，周期结束日也不同，
   需逐账号展示而非取一个全局值。
3. **额度可能包含非 token 费用** —— 例如云沙箱计算费。
   排查「为什么花得比预期多」时要先确认口径，不要只看模型调用费用。

### 3.7 代理池复用

独立「代理池」插件（`src/js/pages/openai/plugins/ProxyPoolPlugin.jsx`，
后端 `backend-go/internal/proxypool/`）提供可复用出口：

- 前端：`fetch('/api/proxypool')` 拉池列表，用 `Select` 选 `proxyPoolId`。
- 后端：通过注入的 `ProxyPoolSelector`（`SelectProxy(ctx, poolID, sessionKey)`）按请求轮询出口，
  `ReportResult` 回写转发结果与健康数据。
- 优先级：手动代理列表 > 独立代理池 > 网关端点代理池。

### 3.8 后台任务的启动方式

插件没有统一的 `Start()` 入口，由 `server.go` 显式调用各启动方法，
且都用 `sync.Once` 保护避免重复启动：

```go
server.<plugin>.StartCallStatsFlush(warmupCtx)   // 调用计数定期落盘
server.<plugin>.StartAutoRefresh(warmupCtx)      // token 自动刷新
```

约定：接受 `context.Context`，在 `ctx.Done()` 时做最后一次落盘再退出。
纯内存态（如冷却记录、轮询游标）**不持久化**，重启即清空 —— 避免把瞬时故障固化。

### 3.9 模型目录的刷新策略

**当前所有插件都不自动刷新模型列表**，这是有意为之：

- 模型目录变化很慢（上游通常几个月才增删一次）；
- 后端本身有缓存（`catalog` 的 `modelCacheAt`，默认 10 分钟），前端频繁刷也拿不到新数据；
- 定时轮询只会增加无效请求。

因此模型列表的加载时机是：

1. 组件挂载时加载一次；
2. 账号变更后顺带重载（授权成功、删除账号、批量启停）；
3. 用户手动触发（卡片 `actions` 里的「刷新目录」按钮）。

**若确需自动刷新**，必须满足两个条件，否则宁可手动：

```jsx
useEffect(() => {
  const timer = setInterval(() => {
    // 仅页面可见时刷新，避免后台标签页持续打接口
    if (document.visibilityState === 'visible') loadModels();
  }, 10 * 60 * 1000);   // 间隔不低于 10 分钟，与后端缓存对齐
  return () => clearInterval(timer);
}, []);
```

注意区分：登录流程的轮询（`setInterval` 打 `/login/poll`）与模型刷新是两回事，
前者仅在登录弹窗打开期间存在，不要把它当成模型自动刷新。

## 四、调试方法论

多数协议结论来自「先写独立探针，再落地插件」，建议按此顺序：

1. **独立探针**：在临时目录写一个不依赖项目的脚本，跑通
   「授权 → 拿 token → 打端点 → 刷新」全链路，确认协议事实；
2. **最小验证**：每个假设用最小请求验证（如用假 token 对比错误响应来判定鉴权路径）；
3. **源码为准**：能拿到上游源码时直接查鉴权、准入、计费相关文件，比读文档可靠；
4. **落地后回归**：把探针阶段发现的边界写成单测（游标回绕、快照失效、冷却回落等）。

## 五、样式红线

- 只用 Kumo 组件 + 本文模板；不引入散落的硬编码颜色（对照 `docs/standards/重构验证与例外清单.md`）。
- 不在页面里写说明性正文段落；描述一律走 `title` 悬浮。
- 删除/危险操作使用 Kumo `DeleteResource` 或标准 confirm（配合 `useConfirmPress` 二次确认）。
- hover 颜色变化即时生效，不用 `transition-colors` / `duration-*`。
- 卡片不用 `border + shadow` 组合，用 `ring ring-kumo-line`；双栏 grid 加 `items-start` 防卡片等高拉伸。
- 图标用单色 SVG + `createAssetIcon`，随主题自适应。
- **不在 Kumo 组件内叠加字号缩放**（`text-[0.8em]` 及以下）——见 2.4。
- **表格必须两层结构**（`LayerCard` > `overflow-x-auto` > `Table`）——见 2.3。
- **不嵌套表格**；**不嵌套 LayerCard**；**不用自绘进度条**。
- **不在表格里重复提供批量操作入口**（表头开关已足够）——见 2.8。

# 新模块接入指南

最后更新：2026-07-07

本指南用于新增或大改业务模块。当前项目默认使用 React + Kumo 前端、Go Manifest 后端和 SQLite，不再新增旧 Express / `modules/*-api` 模块。

配套文档分工：

- 本文：**接入清单**——每层要改哪些文件、按什么顺序、验收跑什么。
- [开发指南](./开发指南.md)：**代码模板**——具体到 handler、页面、store 注册的可复制片段。
- [云厂商模块开发指南](../standards/云厂商模块开发指南.md)：**实操手册**——带真实模块实例与踩坑清单。

## 1. 明确模块 ID

模块 ID 应短小、稳定，并与路由、设置和文档保持一致，例如：

- `openai`
- `gemini-cli`
- `server`
- `cloudflare`
- `notification`

新增模块前先确认它是否应该是已有模块的子能力，而不是新的导航入口。

## 2. 后端模块

推荐结构：

```text
backend-go/internal/example/
├── service.go
├── service_test.go
└── types.go
```

要求：

- 使用 Go 标准库 HTTP handler 形态，保持接口窄而清晰。
- 输入必须校验，敏感写接口要考虑鉴权、2FA、限流或审计日志。
- SQLite schema 必须幂等，使用 `CREATE TABLE IF NOT EXISTS` 和必要索引。
- 表名带模块前缀，避免与其他模块冲突。
- 数据库读写集中在模块内部，不在 server dispatch 中散落 SQL。
- 模块内部不要直接依赖其他模块表的外键；跨模块数据通过明确服务调用协调。

## 3. 路由注册

新增外部可调用 API 时，至少更新：

1. `backend-go/internal/manifest/manifest.go`
2. `backend-go/internal/server/server.go` 或对应 server dispatch 位置
3. 相关 Go 测试

路由清单要明确：

- 是否需要 session auth、API key、agent key 或 public。
- 是否是 JSON、stream、websocket/realtime 响应。
- 是 exact、prefix 还是 pattern 匹配。
- 是否会暴露在 `/v1` 或 OpenAI-compatible 接口中。

验证：

```bash
npm run governance:check
node tools/backend-route-inventory.mjs
npm run backend-go:test
```

## 4. 前端页面

新增页面：

```text
src/js/pages/ExamplePage.jsx
```

通常需要同步：

1. `src/js/store.js` 的模块配置、默认顺序和显隐。
2. `src/js/components/MainLayout.jsx` 的页面 import、图标和渲染映射。
3. 需要时更新文档索引和模块说明。

模块 path 默认应和模块 ID 保持一致。特殊 path 必须有明确理由，并避免破坏已有书签。

## 5. 设置同步

用户设置会管理模块显隐、顺序和部分 UI 偏好。新增模块后确认：

- 默认模块顺序包含该模块。
- 默认显隐逻辑不会遗漏该模块。
- 后端用户设置不会过滤掉该模块。
- 设置页能显示、排序、保存并恢复该模块。

## 6. 前端 UI 约束

组件选择、密度、表格、图表、删除确认、复制文本等全部约束以 [Kumo UI 规则](../standards/Kumo%20UI%20规则.md) 为准，布局与滚动模式以 [前端布局约定](../standards/前端布局约定.md) 为准。新增模块不做例外，例外须登记到 [重构验证与例外清单](../standards/重构验证与例外清单.md)。

## 7. 空态、加载和错误

每个页面至少处理：

- 首次加载。
- 空数据。
- API 失败。
- 保存中或删除中。
- 窄屏布局。
- 暗色主题。

加载占位使用 Kumo `SkeletonLine`、`Loader` 或 Kumo Chart 的 `loading` 状态。不要用本地自绘 loader。

## 8. 验收

至少运行：

```bash
npm run audit:fast
npm run backend-go:test
node tools/backend-route-inventory.mjs
```

涉及后端运行态时，再对正在运行的 Go 后端执行：

```bash
npm run backend-go:smoke
```

新增页面还要做浏览器 smoke：

- 直接访问路由不白屏。
- 侧栏高亮正确。
- 空数据可读。
- 主要弹窗可打开关闭。
- 控制台无 React runtime error。
- 窄屏下内容不重叠。

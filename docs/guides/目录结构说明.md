# 目录结构说明

最后更新：2026-09-08

本文描述当前仓库的主要目录。运行时数据、构建产物和本机临时文件不应提交。

```text
api-monitor/
├── agent-rust/            # Rust Agent 客户端
│   ├── src/
│   │   ├── main.rs        # Agent 主程序
│   │   ├── collector.rs   # 指标采集
│   │   └── docker.rs      # Docker 管理
│   └── Cargo.toml
├── backup/                # 备份数据，忽略提交
├── backend-go/            # Go 后端服务
│   ├── cmd/
│   │   └── api-monitor/   # 主程序入口
│   ├── data/              # 后端运行时数据，忽略提交
│   ├── internal/          # 内部包
│   │   ├── server/        # HTTP 服务器装配
│   │   ├── manifest/      # 路由清单（路由治理真源）
│   │   ├── serveragent/   # Agent 通信与主机管理
│   │   └── ...            # 其他业务模块（50+ 个包）
│   ├── tmp/               # 后端临时文件，忽略提交
│   └── go.mod
├── docs/                  # 项目文档（分层见下）
├── plugin/                # 浏览器扩展等插件
├── public/                # 静态资源
├── src/                   # 前端源码
│   ├── css/app.css        # Tailwind 与全局样式入口
│   ├── index.html         # HTML 入口
│   └── js/
│       ├── main.jsx       # React 入口
│       ├── App.jsx        # 根组件与路由
│       ├── store.js       # Zustand 状态管理
│       ├── components/    # 通用组件与页面组件
│       ├── pages/         # 业务页面
│       ├── modules/       # 前端工具模块
│       └── composables/   # 组合式工具函数
├── test/                  # 测试资源
├── tools/                 # 工程治理与检查脚本
├── data/                  # 运行时数据，忽略提交
├── dist/                  # 前端构建产物，忽略提交
├── Dockerfile             # 容器构建
├── docker-compose.yml     # 容器编排
├── package.json           # 前端与工程脚本
├── vite.config.mjs        # Vite 配置
└── .env                   # 环境变量（需自行创建，忽略提交）
```

## 后端

- `backend-go/cmd/api-monitor`：主程序入口。
- `backend-go/internal/server`：HTTP 服务装配。
- `backend-go/internal/manifest`：路由清单与治理基线。
- `backend-go/internal/*`：按业务模块拆分的内部包（auth、settings、serveragent、cloudflare、openai、filebox、uptime、notification、oracle、gcp、huawei、m365、cronjobs 等）。
- `backend-go/internal/serveragent`：主机实例、Agent 通信、监控指标、终端和公开主机状态页。
- `backend-go/internal/uptime`：可用性监测和公开可用性状态页。

## 前端

- `src/js/main.jsx`：前端入口。
- `src/js/App.jsx`：应用根组件与路由。
- `src/js/pages`：业务页面。
- `src/js/components`：通用组件与页面组件。
- `src/js/components/ui`：项目内封装的 Kumo 风格基础组件。
- `src/js/modules`：前端工具模块。
- `src/js/composables`：组合式工具函数。
- `src/css/app.css`：Tailwind 与全局样式入口。

## 文档

文档按用途分层，根目录只保留索引：

- `docs/README.md`：文档索引；新文档该放哪一层见其中的「新增文档放哪里」。
- `docs/guides/`：上手与流程（开发指南、后端启动、贡献指南、待办闭环、版本管理、目录结构说明）。
- `docs/architecture/`：架构与接口契约（项目架构详解、设计文档、API 接口文档、各模块路由清单）。
- `docs/standards/`：强制性规范（Kumo UI 规则、前端布局约定、模块开发指南、卡片库规范等）。
- `docs/adr/`：架构决策记录。
- `docs/prd/`：需求文档，多数已实现。
- `docs/reference/`：上游组件资料或生成型参考，不代表项目当前状态。
- `docs/plugins/`、`docs/gcp-api-contracts/`：插件登记清单与 GCP API 契约快照。
- `docs/archive/`：历史与一次性文档（巡检、审计、交接、迁移记录），不视为现行标准。

移动或重命名文档后运行 `npm run docs:check` 校验内部链接。

## 不提交内容

- `data/`
- `dist/`
- `node_modules/`
- `.env`
- `backend-go/data/`
- 本机路径、临时会话目录、日志、数据库备份和真实密钥
